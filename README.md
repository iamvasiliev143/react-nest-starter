# React + NestJS Starter

Шаблон одного репозитория с React и Vite в `web/` и NestJS с `NodeAdapter` в `api/`. Включает проверки, интеграцию Telegram Mini App и рабочий процесс для Claude Code, Codex и Notion.

## Запуск

Для воспроизводимого локального запуска используй Node.js 22.23.2, npm 10.9.8 и Docker. Для запуска API нужны настройки PostgreSQL, Redis и S3. Доступность всех трёх сервисов проверяют readiness и тесты.

```sh
npm run setup
npm ci
npm run hooks:install
docker compose up -d --wait postgres redis s3
docker compose run --rm --no-deps s3-buckets
npm run db:migrate
npm run dev
```

Тесты API используют те же контейнеры, но отдельные хранилища: базу `starter_test` в PostgreSQL, уникальный префикс ключей в Redis DB 1 и бакет `starter-test`.

Открой [интерфейс](http://127.0.0.1:5173). Vite проксирует `/api/*` на NestJS по адресу `127.0.0.1:3000`. Для запуска одного приложения используй `npm run dev -w web` или `npm run dev -w api`.

## Стек и возможности

React 19, Vite 8 и TypeScript используются для интерфейса. Маршруты построены на React Router, серверное состояние — на TanStack Query, формы — на React Hook Form и Zod, даты — на date-fns. NestJS 12 работает через NodeAdapter. Данные хранятся в PostgreSQL с Drizzle, Redis и S3-совместимом хранилище. Для фоновых задач подключён BullMQ, для realtime — Socket.IO с Redis-адаптером.

## Переменные окружения

`npm run setup` создаёт корневой `.env` из `.env.example` и `api/.env` из `api/.env.example`. Повторный запуск сохраняет существующие значения. Оба рабочих env-файла исключены из Git. Данные примеров соответствуют локальному Docker Compose. При переносе на другой хостинг задавай его адреса и учётные данные.

### API — `api/.env`

API читает конфигурацию через `@nestjs/config` и проверяет её Zod-схемой при запуске. Переменные окружения процесса имеют приоритет над env-файлом. Обязательные значения должны быть заполнены даже для запуска публичных маршрутов.

| Переменная             | Значение в локальном примере или default                    | Назначение                                                                                                                        |
| ---------------------- | ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `NODE_ENV`             | `development`                                               | Режим `development`, `test` или `production`. В production используются JSON-логи, Swagger отключён.                              |
| `HOST`                 | `127.0.0.1`                                                 | Адрес привязки HTTP-сервера.                                                                                                      |
| `PORT`                 | `3000`                                                      | Порт HTTP-сервера. При изменении согласуй proxy в `web/vite.config.ts` и адрес API в проверках.                                   |
| `DATABASE_URL`         | `postgresql://starter:starter-local@127.0.0.1:5434/starter` | Обязательное подключение PostgreSQL. Поддерживаются схемы `postgres:` и `postgresql:`.                                            |
| `REDIS_URL`            | `redis://127.0.0.1:6380`                                    | Обязательный Redis для общих лимитов запросов и realtime.                                                                         |
| `QUEUE_REDIS_URL`      | `redis://127.0.0.1:6380/5`                                  | Подключение BullMQ. При пустом значении используется `REDIS_URL`.                                                                 |
| `REALTIME_CHANNEL`     | `starter-api:realtime`                                      | Префикс канала Socket.IO. Все реплики одного приложения используют одно значение. Для отдельных приложений задай разные префиксы. |
| `THROTTLER_KEY_PREFIX` | `throttler`                                                 | Префикс ключей лимитов. Разрешены буквы, цифры, `:`, `_` и `-`.                                                                   |
| `S3_ENDPOINT`          | `http://127.0.0.1:9010`                                     | Endpoint S3-совместимого хранилища. Пустое значение позволяет SDK использовать endpoint AWS для региона.                          |
| `S3_REGION`            | `us-east-1`                                                 | Регион S3.                                                                                                                        |
| `S3_BUCKET`            | `starter`                                                   | Обязательное имя бакета, минимум три символа.                                                                                     |
| `S3_ACCESS_KEY_ID`     | `starter`                                                   | Обязательный ключ доступа к S3.                                                                                                   |
| `S3_SECRET_ACCESS_KEY` | `starter-local-secret`                                      | Обязательный секрет S3.                                                                                                           |
| `TELEGRAM_BOT_TOKEN`   | Пусто                                                       | Токен бота. Заполняется вместе с `AUTH_TOKEN_SECRET`.                                                                             |
| `AUTH_TOKEN_SECRET`    | Пусто                                                       | Секрет подписи access-токенов, минимум 32 символа. Заполняется вместе с токеном бота.                                             |
| `OBSERVE_APP_KEY`      | Пусто                                                       | Ключ Observe. Заполняется вместе с `OBSERVE_APP_SECRET`.                                                                          |
| `OBSERVE_APP_SECRET`   | Пусто                                                       | Секрет Observe. При заполненной паре включается отправка трасс и логов.                                                           |

Обе пары необязательных ключей валидируются целиком. При пустой паре Telegram доступны публичные страницы, а вход отвечает `503`. При пустой паре Observe работают локальные Nest-логи.

### Кошелёк TON — `web/.env.local`

Чтобы включить подключение кошелька, задай `VITE_TONCONNECT_MANIFEST_URL` с публичным HTTPS-адресом манифеста до запуска Vite или сборки фронтенда. Для CI передай переменную в окружение шага сборки. Vite записывает её в клиентский код при сборке. Опубликуй манифест с полями `url`, `name` и `iconUrl` и разреши доступ к нему без авторизации. Подробности есть в [документации TON Connect](https://docs.ton.org/applications/ton-connect/get-started).

### Проверки и инструменты

| Переменная                | Когда используется                                                                                                                      |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `PLAYWRIGHT_CHANNEL`      | Выбор установленного браузера для e2e, например `msedge`. По умолчанию Playwright использует Chromium.                                  |
| `CI`                      | Устанавливается CI-средой. Playwright запускает собственный dev-сервер. Локально может использовать уже работающий сервер.              |
| `TEST_REDIS_URL`          | Переопределяет Redis для отдельного теста BullMQ. Default — `redis://127.0.0.1:6380`. Тест использует Redis DB 3 и 4.                   |
| `OBSERVE_SERVICE_VERSION` | Необязательная версия сервиса для SDK Observe, задаваемая окружением деплоя.                                                            |
| `LEFTHOOK`                | Служебная настройка Lefthook. В CI при `npm ci` используется `0`, чтобы установка пакетов обходилась без установки локальных Git hooks. |

HTTP-тесты берут `DATABASE_URL`, `REDIS_URL` и S3-настройки из окружения процесса или используют локальные defaults из тестового helper. Для PostgreSQL создаётся `starter_test`, для Redis используются уникальные префиксы, для S3 — `starter-test`. Перед `npm run check` подними хранилища командами из раздела запуска.

Vite проксирует API на `http://127.0.0.1:3000`. В production клиент обращается к API на том же origin. Значения с префиксом `VITE_` становятся частью браузерной сборки, поэтому для них подходят только публичные настройки.

## Создание проекта из шаблона

В новом клоне выполните `npm run setup -- --name my-project`. Команда переименует корневой пакет и workspaces в `my-project`, `my-project-api`, `my-project-web`, синхронизирует npm lockfile и создаст `api/.env` для API и корневой `.env` для MCP. Повторный запуск сохраняет существующие env-файлы. Без `--name` используются текущие имена.

Если при первом запуске задана переменная окружения `TELEGRAM_BOT_TOKEN`, setup запишет её в новый env-файл и сгенерирует секрет доступа. Значения секретов в вывод не попадают. При пустом токене авторизация Telegram остаётся выключенной. Существующие настройки редактируйте в `api/.env`.

Команда проверяет Node.js, доступность npm и Docker и TCP-порты настроенных PostgreSQL, Redis и S3. После переименования выполните `npm ci` для обновления workspace-ссылок и `npm run hooks:install`. Команды запуска контейнеров, создания бакетов и миграций приведены выше.

## Структура фронтенда

- `web/src/app/` содержит bootstrap, провайдеры, маршруты и композицию страниц.
- `web/src/modules/<feature>/` содержит компоненты, API-запросы, состояние и тесты фичи. Авторизация, проверка API и время расположены в `auth/`, `health/` и `time/`.
- `web/src/common/` содержит HTTP-клиент, обработку ошибок и адаптер Telegram. Общая инфраструктура независима от модулей и приложения.
- `web/src/i18n/` содержит переводы по языкам и разделам. Типы OpenAPI генерируются в `web/src/api-schema.d.ts`.

## Структура API

- `api/src/modules/` содержит фичи NestJS. Модуль владеет своими контроллерами, сервисами, DTO (`dto/`) и внутренними типами (`interfaces/`). Индикаторы readiness лежат в `modules/health/indicators/`.
- `api/src/database/` содержит по папке на хранилище. В `postgres/` лежат сервис подключения, таблицы Drizzle (`schema/<entity>.schema.ts`), запросы (`repositories/<entity>.repository.ts`) и миграции (`migrations/`). Имена сущностей в файлах и классах схем и репозиториев используй в единственном числе, например `user.schema.ts`, `userSchema` и `UserRepository`. В `redis/` лежит клиент Redis, в `s3/` — диск файлового хранилища.
- `api/src/common/` содержит общую инфраструктуру: конфигурацию, Observe, лимиты запросов в Redis (`throttler/`) и i18n.

Для правил размещения контрактов и зависимостей между фичами смотри [nestjs-practices](.claude/skills/nestjs-practices/SKILL.md).

## HTTP API и авторизация

| Маршрут                                  | Доступ               | Назначение                                                       |
| ---------------------------------------- | -------------------- | ---------------------------------------------------------------- |
| `GET /api/health`                        | Публичный            | Liveness процесса.                                               |
| `GET /api/health/ready`                  | Публичный            | Readiness PostgreSQL, Redis и S3. При отказе возвращается `503`. |
| `GET /api/v1/greeting`                   | Публичный            | Пример локализации по `Accept-Language`, языки `en` и `ru`.      |
| `POST /api/v1/auth/telegram`             | Публичный            | Проверка Telegram `initData` и выдача access-токена.             |
| `GET /api/v1/auth/me`                    | Bearer               | Профиль текущего пользователя.                                   |
| `POST /api/v1/client-errors`             | Публичный, с лимитом | Приём категорий клиентских ошибок.                               |
| `GET /api/docs`, `GET /api/openapi.json` | Development и test   | Swagger UI и OpenAPI.                                            |

Для запуска Mini App настрой бота и публичный HTTPS-адрес интерфейса в Telegram. На сервер передаётся исходная строка `initData`, её подпись и свежесть проверяются до сохранения профиля и выдачи токена. Access-токен действует 15 минут. Клиент хранит его в памяти и при `401` завершает сессию с возможностью повторного входа.

Секрет доступа можно сгенерировать локально командой `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"` и записать результат в `api/.env`. Setup генерирует секрет автоматически, если при создании env-файла в окружении уже задан `TELEGRAM_BOT_TOKEN`.

Глобальные DTO ошибок описывают `400`, `401`, `403`, `404`, `429`, `500` и `503`. Ответ содержит `statusCode`, `code`, `message`, `requestId`; `fieldErrors` добавляется для ошибок валидации `400`. Идентификатор запроса также приходит в `X-Request-Id`. Readiness сохраняет поля Terminus с состояниями зависимостей.

## Очереди, realtime и ошибки интерфейса

BullMQ использует `QUEUE_REDIS_URL`, три попытки и exponential backoff. Конкретные очереди и processors добавляются в модуль-владелец фичи. Локальный Redis запускается без persistence, поэтому хранение очередей в эксплуатации настраивается на выбранном Redis-хостинге.

Socket.IO использует путь `/api/socket.io` и namespace `/realtime`. Access-токен передаётся как `auth: { token: accessToken }`, транспорт — `websocket`. Redis-адаптер передаёт события между репликами API. Соединение закрывается при истечении токена.

Error Boundary и обработчик ошибки bootstrap показывают экран восстановления. Клиент отправляет категории `source`, `kind`, `page` с лимитом пять отчётов на загрузку. Сервер валидирует их, ограничивает частоту и пишет в Nest-лог, который при включённом Observe передаётся в мониторинг.

## Git и релизы

Постоянные ветки проекта — `main`, `develop` и `staging`. Начинай обычную задачу от `develop` и открывай PR в неё. Релиз-кандидат проходит из `release/*` через `staging` в `main`. [Порядок работы с ветками, ревью и релизами](docs/git-workflow.md)

## Работа с агентами

1. Зафиксируй цель, критерии готовности и ограничения. Для задачи из Notion приложи ссылку на карточку.
2. Из корня запусти `npm run ai:claude -- --agent tech-lead` или открой проект в Codex. Команда Claude загружает настройки MCP из корневого `.env`. Роли и выбор скилов описаны в [справочнике команды](docs/team.md), общие правила лежат в [AGENTS.md](AGENTS.md).
3. Если поток между модулями неизвестен, используй `/engram-context` в Claude Code или `$engram-context` в Codex. Граф хранится в `.engram/`. Сводка доступна через `npm run graph:summary`.
4. Перед сдачей запусти проверки и передай актуальный diff на независимое ревью. Для веток и PR используй `/git-workflow` в Claude Code или `$git-workflow` в Codex. Добавляй ссылку на карточку в PR.

## Деплой

Docker Compose используется для локальных PostgreSQL, Redis и S3. В разработке запускай Vite и NestJS через `npm run dev`.

После сборки раздавай `web/dist` как статические файлы и направляй навигацию SPA на `index.html`. Проксируй запросы `/api/*` с того же домена на NestJS, сохраняя префикс `/api`. Запусти собранный API через `npm run start -w api`. Адрес и порт задаются переменными `HOST` и `PORT`.

## Обновления зависимостей и CI

Dependabot проверяет npm и GitHub Actions по понедельникам в 09:00 по Киеву и открывает PR в `develop`. Minor/patch npm-обновления группируются, major проверяются отдельно. Типы Node поддерживаются в major 22, соответствующем runtime CI. Для уязвимых транзитивных зависимостей Engram и Drizzle Kit применены адресные npm overrides в корневом `package.json`.

Workflow `Check` проверяет маршрут PR и сообщения коммитов, воспроизводимость OpenAPI, общий `check` и Playwright. Для успешного push в `staging` сохраняется release-архив. Статус задания и его логи доступны в GitHub Actions. Запуск workflow зависит также от доступности и биллинга GitHub Actions для аккаунта.

Для production используй переменные окружения хостинга, отдельные учётные данные хранилищ и `NODE_ENV=production`. Применяй миграции командой `npm run migrate -w api`, запускай API и раздавай статический `web/dist`. Для нескольких реплик согласуй Redis, очередь, префиксы лимитов и канал realtime. Состав проверенного артефакта и порядок выпуска описаны в [руководстве по Git и релизам](docs/git-workflow.md).
