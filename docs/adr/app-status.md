# Статус Mini App и режим технических работ

Храним режим в одной записи PostgreSQL. Запись переживает перезапуск, доступна всем репликам API и может обновляться будущей админкой с отдельной политикой доступа. До появления админки режим может менять оператор с доступом к базе.

NestJS кеширует результат чтения на одну секунду в памяти каждой реплики и объединяет параллельные обращения. При недоступности записи пользовательские HTTP-маршруты отвечают `503`; инфраструктурная проверка процесса остаётся доступной. После изменения режима реплика обновляет состояние при первом обращении по истечении кеша. Запущенные операции завершаются в обычном порядке.

Опрос из активного Mini App выполняется раз в пять секунд и при возврате в приложение. При 10 000 активных окон это около 2 000 HTTP-запросов в секунду и примерно одно чтение PostgreSQL в секунду на каждую загруженную реплику. Redis потребовал бы отдельной синхронизации с PostgreSQL и не уменьшил бы число запросов клиента. Если измерения покажут, что ограничение создаёт именно поток HTTP-запросов, можно отдельно оценить короткое кеширование на прокси или серверную рассылку статуса.
