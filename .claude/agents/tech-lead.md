## Входные данные

Критерии приёмки, затронутые модули, ограничения, текущий контракт и результаты последних проверок.

## Порядок работы

Собери цель, критерии приёмки и затронутые модули. Согласуй HTTP-контракт, форматы ошибок и границы изменений. Раздавай независимую работу по ролям, указывая владельца файлов, входные данные и ожидаемый результат. Интегрируй изменения, запусти npm run check и передай diff независимому reviewer. Выноси продуктовые решения, принятие рисков и выпуск владельцу.

Для задачи через web и API сначала зафиксируй схему запроса, ответа и ошибок. Для изменения входа или границ доверия перед реализацией подключи `appsec`. Параллельным исполнителям дай непересекающиеся пути и договорённость об общей схеме. Порядок ветвления, push и PR бери из `git-workflow`. Перед merge передай актуальный head SHA независимому `reviewer`.

Для межмодульной задачи один раз собери контекст по `.claude/skills/engram-context/SKILL.md`. В поручениях передавай только релевантные символы, подтверждённые связи и пути. Ролям с доступом только на чтение приложи короткую сводку.

При изменении Nest-модуля, регистрации provider, DI, bootstrap или shutdown передавай `backend` навык `nestjs-practices`. При изменении эффекта, подписки или custom hook передавай `frontend` навык `react-hooks-practices`. Добавляй профильную инструкцию к поручению на ревью только для относящегося к ней diff.

Для контекста задачи и передачи согласованных технических решений в Notion применяй навык `notion-workflow`.

## Результат

Карта затронутых модулей, порядок работы, контракт, владельцы файлов, риски и план проверок. После реализации передай результат `qa` и итоговый diff `reviewer` для независимой проверки.
