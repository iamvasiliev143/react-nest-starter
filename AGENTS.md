# Работа с репозиторием

- `web/` содержит React-интерфейс. `api/` содержит NestJS, серверную бизнес-логику и интеграции.
- Новый HTTP-маршрут использует глобальный префикс `/api`. Фронтенд обращается к API по относительным URL.
- Валидируй внешние данные на серверной границе. Храни секреты вне Git и вне переменных, доступных сборке Vite.
- Описывай новые контракты рядом с реализацией и обновляй потребителей в том же изменении.
- Перед сдачей запусти `npm run check` из корня. Укажи фактический результат и явно назови проверки, которые не удалось запустить.
- В итогах кратко укажи изменения, способ проверки и важные ограничения.

## Структура API

Группируй фичи в `api/src/modules/`. Храни DTO и внутренние типы в модуле-владельце, а соседним фичам предоставляй доступ через явно экспортируемые провайдеры. `api/src/database/` отвечает за подключение к БД и схему Drizzle. `api/src/common/` содержит инфраструктуру, которую использует приложение. Оба слоя свободны от зависимостей на фичи. [Правила NestJS](.claude/skills/nestjs-practices/SKILL.md)

## Git, PR и релизы

При работе с ветками, коммитами, push и PR применяй `git-workflow`. Обычные рабочие ветки начинай от `develop`. Ревью плана проводи перед изменением границ доверия, контракта или выкладки. Перед merge передай актуальный diff `reviewer` и проверь CI. Для выпуска применяй `release-handoff` и получи решение владельца. [Ветки, проверки и релизы](docs/git-workflow.md)

## Работа с Notion

Используй `notion-workflow` для задач, документации, решений и отчётности в Notion. Когда работа привязана к карточке, прочитай её и связанные решения перед реализацией. Пиши в найденную запись, когда работа включает обновление Notion. Для статуса и отчёта используй фактические результаты проверок. [Правила проекта в Notion](docs/notion.md)

## Навигация по коду с Engram

Для неизвестного потока, связей между модулями и оценки влияния используй [engram-context](.claude/skills/engram-context/SKILL.md). Для известного файла или небольшого diff открой исходники напрямую. Техлид собирает краткую сводку, если она нужна нескольким ролям, и передаёт каждой роли релевантные ссылки. Сверяй выводы графа с кодом.

## Делегирование

Смотри [состав команды и рабочий процесс](docs/team.md). Для задачи выбери нужные роли, передай им контракт и критерии готовности. После реализации организуй независимое ревью и собери фактические результаты проверок. В задачах с границами доверия используй AppSec-ревью и независимую оценку защитных тестов.

Для повторяемой работы сверяй задачу с [навыками по этапам](docs/team.md#навыки-по-этапам). Указывай подходящий навык в задании при делегировании.

### Правила фреймворков

- Используй `nestjs-practices` при изменении границ Nest-модулей, регистрации provider, DI или жизненного цикла в `api/src/`.
- Используй `react-hooks-practices` при изменении эффектов, подписок, таймеров или custom hooks в `web/src/`.
- Используй `telegram-mini-app-webview` при изменении запуска Mini App, темы, viewport, safe areas, нативных кнопок или проверки WebView. Для подписи, токенов и прав используй `telegram-auth-change`.
- Для задач только по документации, тексту интерфейса или стилям достаточно применимых общих инструкций.
